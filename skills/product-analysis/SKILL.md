# Product Analysis

Gather user intent through structured questions and synthesize into a Product Requirements Definition (PRD).

## When to Use

This skill activates when:
- Starting a new product
- User wants to define what to build
- Need to capture problem, users, and goals
- PRD.md needs to be created or updated
- User want to define new parts of pProduct

## Core Workflow

### Step 1: Understand the Problem

Ask about the problem being solved:
- What problem does this product address?
- Who experiences this problem?
- How do they solve it today?

### Step 2: Define Target Users

Clarify who the product serves:
- Who are the primary users?
- What are their goals?
- What constraints do they have?

### Step 3: Capture Value Proposition

Identify the unique value:
- What makes this solution valuable?
- How is it different from alternatives?
- What's the core benefit?

### Step 4: Define MVP Tasks

Scope the initial version:
- What tasks are essential for launch?
- What can wait for later?
- What's explicitly out of scope?

### Step 5: Create PRD

Synthesize into Docs/Product/PRD.md:
- Use `templates/PRD.md` as structure
- Keep descriptions concise
- Mark assumptions and open questions

## Key Guidelines

- **Ask before assuming**: Clarify unclear requirements
- **Keep scope minimal**: Focus on what's essential for MVP
- **Document constraints**: Capture technical and business limitations
- **Identify risks**: Note assumptions that need validation

## Validation Checklist

- [ ] Problem statement is clear and specific
- [ ] Target users are defined
- [ ] Value proposition articulated
- [ ] MVP tasks identified and prioritized
- [ ] Constraints and scope documented
- [ ] PRD.md created/updated in Docs/Product/
